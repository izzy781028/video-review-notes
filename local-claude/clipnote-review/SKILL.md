# 片語審片（本機 Claude）

片語是阿湯的線上審片工具：影片放在 Google Drive 的「片語審片」資料夾，阿湯和客戶在片語上看片、留時間碼意見。這個 skill 讓本機的 Claude 接上這個流程：

1. 剪好一版 → 輸出審片檔 → 放進雲端資料夾（片語就會出現這支片）
2. 有新的審片意見 → 讀進來 → 使用者自己的意見**直接照做**；客戶的意見**逐則由使用者決定**改不改、怎麼改
3. 改完 → 標記「已修改」

所有動作都透過同一個資料夾裡的 `clipnote.py`（只用 Python 內建模組，不用安裝套件）：

```bash
python3 ~/.claude/skills/clipnote-review/clipnote.py <指令>
```

以下用 `clipnote` 代表上面這串。

## 開始前先檢查

每次用這個 skill，先跑：

```bash
clipnote check
```

- 出現「片語連線 ✓」和「雲端資料夾 ✓」就可以繼續。
- 設定檔不存在或缺值：照下面「第一次設定」帶使用者完成，**不要自己猜金鑰或網址**。

### 第一次設定（只做一次）

1. 建立 `~/.config/clipnote/config.env`（範本在這個資料夾的 `config.env.example`），內容：
   ```
   CLIPNOTE_URL=https://<片語的網址>.pages.dev
   CF_ACCESS_CLIENT_ID=<Cloudflare 服務權杖 Client ID>
   CF_ACCESS_CLIENT_SECRET=<Cloudflare 服務權杖 Client Secret>
   CLIPNOTE_DRIVE_DIR=<電腦上「片語審片」資料夾的路徑>
   ```
2. 服務權杖由使用者在 Cloudflare Zero Trust 建立（步驟在片語 README「本機 Claude」一節）。請使用者自己把值貼進檔案；不要要求使用者把 Secret 貼在對話裡，也不要把它印出來。
3. `CLIPNOTE_DRIVE_DIR` 是 Google Drive 電腦版同步到本機的路徑，常見位置：
   - macOS：`~/Library/CloudStorage/GoogleDrive-<Email>/我的雲端硬碟/片語審片`
   - Windows：`G:\我的雲端硬碟\片語審片`

   `clipnote check` 找得到時會列出「可能是：…」，請使用者確認後再填。
4. 檔案權限設成只有自己可讀：`chmod 600 ~/.config/clipnote/config.env`

## 雲端資料夾結構

```
我的雲端硬碟/
├─ 片語審片/                          ← 片語只讀這一層，只放「審片小檔」
│  ├─ 20261018_夏日新品_形象片_B Copy.mp4
│  ├─ 20261017_手沖咖啡_Reels_v1.mp4
│  └─ _封存/                           ← 審完、或被新版本取代的檔案移進來（片語不會列出）
│     └─ 2026-10/
└─ 專案/                               ← 不分享給片語
   └─ 2026_夏日新品/
      ├─ 01_素材/
      ├─ 02_專案檔/
      └─ 03_輸出/                       ← 母帶、交片檔（ProRes、4K 等）
```

規則：

- **檔名**：`YYYYMMDD_專案_內容_版本.mp4`。版本的寫法：
  - 主要用 `_A Copy`、`_B Copy`、`_C Copy`…，定剪用 `_Final`（定剪後再改用 `_Final_v2`），例如 `20261018_夏日新品_形象片_B Copy.mp4`。Final 一律排在所有 Copy 之後。
  - 也可以用 `_v1`、`_v2`、`_v3`…。同一支片選一種寫法用到底。
  - 檔名有空格，指令裡要用引號包起來。
  直式片在內容加 `Reels`、`Shorts` 或 `916`。片語依修改時間排序，最新的在最上面。
- **新版本 = 新檔案**：B Copy 改完出 C Copy 或 Final，不要覆蓋舊檔。覆蓋同名檔時 Google Drive 會沿用同一個檔案 ID，舊版的意見會掛到新版上，看起來就亂了。`clipnote upload` 會擋下同名檔。
- **審片檔規格**：720p（直式 720 寬）、H.264、AAC、faststart 的 mp4。ProRes、HEVC、4K 母帶不要放進來，瀏覽器播不了或播不順。
- **封存**：片子核准，或已經出了下一版，就把舊檔移到 `_封存/年-月/`。檔案 ID 不變，意見都還在資料庫裡，只是片語不再列出。移之前先問使用者。
- `專案/` 不要分享給片語的服務帳戶，片語只需要讀「片語審片」。

## 流程一：輸出完一版 → 放進審片資料夾

1. 確認要上傳哪個檔案、專案名稱和版本。看 `clipnote videos` 找這個專案目前最新的版本，新檔用下一個版本（下一個字母的 Copy；使用者說是定剪就用 Final；用 v 編號的專案就加一），沿用這個專案原本的寫法。
2. 母帶或 ProRes、HEVC、4K 這類檔案，一律加 `--proxy` 轉成審片小檔：
   ```bash
   clipnote upload "<輸出的檔案>" --name "20261019_夏日新品_形象片_C Copy.mp4" --proxy
   ```
   本來就是 720p H.264 mp4 的檔案可以不加 `--proxy`，直接複製。
3. 檔名不合規則、或資料夾已有同名檔時，指令會停下來並說明原因：照說明改名，不要繞過。
4. 等 Google Drive 同步上去：
   ```bash
   clipnote wait "20261019_夏日新品_形象片_C Copy.mp4"
   ```
5. 回報使用者：檔名、已經出現在片語，可以打開片語看片或分享給客戶。分享連結要使用者在片語網頁上按「分享給外部審片」，這個 skill 不建立分享連結。

## 流程二：讀新的審片意見 → 依來源處理

使用者問「有沒有新的意見」，或剛開始處理某個專案時：

1. 讀新意見（上次確認之後新增或修改的）：
   ```bash
   clipnote inbox
   ```
   `clipnote inbox --all` 會列出所有還沒完成的意見。需要完整欄位時加 `--json`（`author` 是 `owner` 就是使用者自己，`share:…` 是客戶）。
2. 意見分成兩種來源，處理方式不同：

### 使用者自己的意見（標「你」）：完全照做

- 這些是使用者自己審片時講的，**視為已確認，不用逐則問**。直接整理成待辦清單，告訴使用者「你的 N 則意見我會照做」，然後開始改。
- 只有以下情況才停下來問：看不懂指的是哪裡、沒講清楚要改成怎樣而且猜不出來、或技術上做不到。問的時候一次問完，不要一則一則來回。
- 有「原始口述」時，以原始口述的意思為準；AI 整理和原話有出入就照原話做，並提一句。

### 客戶的意見（標「客戶：名字」）：逐則請使用者決定

- 一則一則列給使用者：時間碼、客戶名字、內容；需要時附上你建議的做法。
- 請使用者對每則說「照改」「不改」或「怎麼改」。**不要替使用者決定客戶意見可不可以改**，你的建議只是參考。
- 使用者決定後立刻記下來：
  ```bash
  clipnote decide <影片> <意見id> accept                       # 照客戶寫的改
  clipnote decide <影片> <意見id> adjust --note "改成…"        # 改，但照使用者說的改法
  clipnote decide <影片> <意見id> reject --note "理由…"        # 不改
  ```
  決定會顯示在片語網頁的這則意見上（只有使用者看得到，客戶看不到）。「不改」的意見會結案，不再出現在待辦裡。
- 使用者還沒決定的客戶意見，不要動手改。

### 共通

- 時間碼寫成 `A → B` 的是範圍意見，要改的是整段。
- 意見下面 `↳` 開頭的是你和客戶的回覆，以最後的共識為準（例如客戶回「可以」就照回覆裡的改法做）。
- 標「從 vN 帶入」的意見是從上一版帶過來的：時間碼可能因為剪接移動了，先在新版找到對應的位置；同一則意見在舊版和新版都會出現時，只處理新版那一則。
- 有畫面位置（x% y%）或箭頭、方框、手繪標記時，可以用 `clipnote shot <影片> <意見id> -o /tmp/<id>.jpg` 存下截圖，再用 Read 看圖，確認指的是哪個元素。
- 影片狀態是「需要修改」或「已核准」時一併告訴使用者，例如：「王小姐把 v2 標為需要修改」。
- 這一批都處理完（自己的意見已排進待辦、客戶意見都有決定）後執行：
  ```bash
  clipnote ack
  ```
  下次 `clipnote inbox` 就只會顯示之後的新意見。

## 流程三：改完 → 標記完成

- 使用者自己的意見：改好就可以標記，不用再問。
- 客戶的意見（照改／改法調整）：改好並請使用者看過後再標記。
  ```bash
  clipnote done <影片名稱或 id> <意見 id>
  ```
  標錯了用 `--undo` 改回。「不改」的意見已經結案，不用標記。
- 影片名稱可以只打一部分（例如 `夏日新品`），對到多支時指令會請你寫完整。
- 全部改完通常就是出下一版：回到流程一，用下一個版本（B Copy → C Copy，定剪出 Final）。

## 開工時自動檢查（選用）

想讓本機 Claude 每次開新對話都先看有沒有新意見，請使用者在 `~/.claude/settings.json` 加上（改這個檔案前先問使用者）：

```json
{
  "hooks": {
    "SessionStart": [
      { "hooks": [ { "type": "command", "command": "python3 ~/.claude/skills/clipnote-review/clipnote.py inbox 2>/dev/null || true" } ] }
    ]
  }
}
```

開新對話時，Claude 會在對話內容裡看到 inbox 的結果。有新意見就主動提一句，問使用者要不要現在逐則確認；沒有就不用講。

## 不要做的事

- 不覆蓋、不刪除「片語審片」裡的檔案；移到 `_封存/` 也要先問。
- 不替使用者決定客戶意見改不改；客戶意見在使用者決定前不動手。
- 不替使用者核准影片（這個 skill 沒有核准的指令，核准請在片語網頁上按）。
- 不把 `config.env` 的內容、服務權杖印出來或貼到任何地方。
- 不把母帶、專案檔、素材放進「片語審片」。

## 指令速查

| 指令 | 用途 |
|---|---|
| `clipnote check` | 檢查設定、連線、雲端資料夾 |
| `clipnote videos` | 片語資料夾裡的影片、狀態、意見數 |
| `clipnote inbox` | 上次確認之後的新意見（`--all` 全部未完成，`--json` 原始資料） |
| `clipnote ack` | 記下這批已確認 |
| `clipnote notes <影片>` | 一支影片的所有意見（`--open` 只看未完成） |
| `clipnote shot <影片> <意見id> -o 檔名` | 存下意見的截圖 |
| `clipnote decide <影片> <意見id> accept\|adjust\|reject [--note 文字]` | 記下使用者對客戶意見的決定 |
| `clipnote done <影片> <意見id>` | 標記已修改（`--undo` 改回） |
| `clipnote upload <檔案> --name <檔名> [--proxy]` | 放進雲端資料夾（`--proxy` 先轉 720p 審片檔） |
| `clipnote wait <檔名>` | 等 Google Drive 同步到片語 |
